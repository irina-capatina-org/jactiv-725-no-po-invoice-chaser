## 1. Solution Overview

The No-PO Invoice Chaser runs each weekday and queries Coupa for invoices in `draft` or `new` status dated within the past seven days. It excludes credit notes and any invoice that has a PO number on at least one invoice line, counts the remainder, and — when that count exceeds zero — posts one Slack Block Kit direct message to the AP SME. On a clean day (count = 0) the workflow ends silently. All writes to Coupa are forbidden; the automation is read-only.

| Project | Type | Entry point | Role |
|---|---|---|---|
| `no-po-invoice-chaser-api` | API Workflow | `code/no-po-invoice-chaser-725/no-po-invoice-chaser-api/Workflow.json` | Single project; query → filter → notify |

## 2. As-Built Architecture

```
Orchestrator time trigger (weekdays 10:00 Europe/Bucharest)
        │
        ▼
  no-po-invoice-chaser-api  (API Workflow, serverless)
        │
        ├─► HTTP_Request_Coupa  ──►  Integration Service: coupa-uipath-test
        │       GET invoices, status=draft|new, last 7 days, limit=50
        │
        └─► HTTP_Request_Slack  ──►  Integration Service: slack-product-test-app
                POST chat.postMessage to WLX9BD8FN  (only when count > 0)
```

Both connector activities use `call: "UiPath.Http"` with `authentication: "connector"` routed through the UiPath HTTP connector to the vendor connector — see `code/no-po-invoice-chaser-725/no-po-invoice-chaser-api/bindings_v2.json`.

**As-built note:** After a build-validation repair, the Slack `body` field is an inline `${{ }}` expression referencing individual workflow variables directly (not the `slackPayload` string variable). As a consequence `Javascript_ComposeSlackPayload`, `Assign_SlackPayload`, and the `slackPayload` variable are dead code — present but not consumed by `HTTP_Request_Slack`. They may be removed by a developer without behaviour change.

## 4. Exception and Error Handling

No retry logic and no secondary notification are implemented (BR-08, BR-09). All failures propagate as unhandled exceptions; the Orchestrator job status is the sole observable signal.

| ID | Failure | Detection point in code | Retry | Job result |
|---|---|---|---|---|
| S1 | Coupa query failure (HTTP 4xx/5xx or connection error) | `HTTP_Request_Coupa` in `Workflow.json` | None | Failed |
| S2 | Slack delivery failure (`ok ≠ true` or HTTP error) | `Javascript_ValidateSlack` in `Workflow.json` — throws `Error` | None | Failed |
| S3 | Credential expired / auth rejected | `HTTP_Request_Coupa` or `HTTP_Request_Slack` in `Workflow.json` | None | Failed |
| S6 | Any other unhandled runtime exception | Anywhere in `Workflow.json` | None | Failed |
| B1 | Credit note invoice | `Javascript_FilterAndCount` — `invoice-type === 'Credit Note'` check | N/A — excluded from count | Run continues |
| B2 | Description-only PO (not on a line) | `Javascript_FilterAndCount` — `invoice-lines[].po-number` / `order-header-num` check only | N/A — counted as missing-PO | Run continues |
| B3 | Zero qualifying invoices | `If_1` branch in `Workflow.json` — `qualifyingCount > 0` | N/A — no Slack sent | Successful |

## 5. Operations Runbook

### Trigger and schedule

The workflow is invoked by an Orchestrator time trigger — weekdays 10:00 Europe/Bucharest, serverless. **The trigger has not yet been provisioned** (Task T5 blocked; left for deploy stage). For manual testing, invoke via:

```bash
uip api-workflow run code/no-po-invoice-chaser-725/no-po-invoice-chaser-api/Workflow.json \
  --input-arguments '{}' --output json
```

Or start a job from Orchestrator once the process is deployed.

### Expected runtime and volume

- Typical runtime: seconds (two HTTP calls + JavaScript).
- Coupa page size: `limit=50`. If daily invoice volume exceeds 50, the count will be understated and pagination logic must be added.
- Job retention: 30 days (active), 180 days (stale) — set in `code/no-po-invoice-chaser-725/resources/solution_folder/process/api/no-po-invoice-chaser-api.json`.

### Normal run log

1. `Javascript_ComputeDateWindow` — produces `windowStart`, `windowEnd`, `runDate`
2. `HTTP_Request_Coupa` — returns invoice array
3. `Javascript_FilterAndCount` — logs nothing; sets `qualifyingCount` and `exclusionLog`
4. `If_1` branch — taken if `qualifyingCount > 0`
5. (If branch taken) `HTTP_Request_Slack` — posts DM; `Javascript_ValidateSlack` confirms `ok: true`
6. `Javascript_LogResult` — emits `qualifying_count=<n>` and `slack_sent=<bool>` to Orchestrator job log (Information)
7. `Response_1` — returns `{ status: 'Successful', qualifying_count, slack_sent }`
